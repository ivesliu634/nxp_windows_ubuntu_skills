# 问题分析与证据判断

## 分析方法

1. 明确目标、参考基准、当前现象和期望差异；记录版本、板型、命令及原始证据来源。
2. 将已观察事实、用户描述、历史经验和待验证推断分开。
3. 把混在一起的阶段或责任拆开，指出当前证据实际支持哪一层结论。
4. 有多个合理解释时，提出能区分它们的最小实验，并说明不同结果各能证明什么、不能证明什么。
5. 收敛到下一条缺失证据或待确认的方向，不为补全流程而扩展到无关构建、传输或上板动作。

分析结果应能回答：现在知道什么、仍不知道什么、下一步最小需要验证什么。
涉及真实执行的实验仍须遵守该动作的授权和核验要求。

## 按问题查阅专题

### `flash.bin`：产物、传输和运行阶段边界

只有出现下列语义歧义时才读取：

- 不清楚当前讨论的是打包产物、传输动作还是运行结果
- 同一个 `flash.bin` 在不同 USB/boot 阶段中的作用被混为一谈
- 把 UUU 成功、写入成功、进入 Fastboot 或最终启动成功互相等同
- 不清楚当前设备阶段和 UUU recipe 如何共同决定实际动作

对应资料：[flash.bin 阶段模型](references/flashbin-stage-model.md)。

### `M` 核：打包、加载、生命周期和运行契约

只有出现下列语义歧义时才读取：

- 把 payload 放在哪里和谁负责加载启动混为一谈
- 不清楚谁负责启动、停止、恢复或资源管理
- 把 `flash.bin`、`bootaux`、Linux remoteproc 当成互斥的单一 owner
- 不清楚 RPMsg、resource table、shared memory 等运行契约与加载路径的关系

对应资料：[M 核职责模型](references/mcore-owner-model.md)。
